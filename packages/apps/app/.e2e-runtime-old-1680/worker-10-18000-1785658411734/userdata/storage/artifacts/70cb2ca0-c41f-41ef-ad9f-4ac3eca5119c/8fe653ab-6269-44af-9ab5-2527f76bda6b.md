# Left Panel as Task Navigation — Concepts

## Decision

**Concept D (Tree Hierarchy) ★** + bottom view-switcher dropdown for swapping between sidebar views. Future views plug into same dropdown via registry. See `04-concept-d-tree-hierarchy.md`.

## Problem

Today: left rail = narrow `w-18` strip with project blobs only.
Want: option to use left panel as **task navigation menu**, not just project switcher.

Tasks currently surface only inside the active project's kanban. No global cross-project task awareness in the sidebar.

## Design Goals

1. Preserve project switching (don't lose existing function — legacy view available in switcher)
2. Make tasks first-class in nav (find / open / track without entering kanban)
3. Configurable — user picks view from a dropdown that scales to N views
4. Keep zen mode (`!w-0`) compatible
5. Drag/reorder still possible
6. Window-drag region (top 10px) preserved for traffic lights

## Five Concepts

| # | Name | Rail width | Projects | Tasks | Tradeoff |
|---|------|-----------|----------|-------|----------|
| A | Expandable Rail | w-18 → w-72 on hover/pin | Always | Slide-out per project | Familiar; reveal-on-demand |
| B | Mode Toggle | w-18 (fixed) | Toggle | Toggle | Simple, but switch cost |
| C | Hybrid Two-Column | w-18 + w-64 | Rail | Wide column | Most info; eats canvas |
| **D ★** | **Tree Hierarchy** | **w-64** | **Inline** | **Inline expand** | **Single-pane; legacy rail still selectable in switcher** |
| E | Filtered Task Feed | w-72 | Filter chip | Flat list | Flat power; no project hier |

See `01..05` for each concept with ASCII wireframes.

## Configuration

Add `sidebar_view` setting: `string` (registry key, default `'projects'`).
Registry pattern — each view = `{ id, label, icon, render, width }`.
View switcher button at bottom of sidebar; opens dropdown with all registered views.
