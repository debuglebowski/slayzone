# Why task `4c812abe` terminal showed "active" (running) mode

**Investigated task**: `4c812abe-6f9a-46b2-ae15-3abdca41f9ff` — Phase 6 react-query + tRPC integration
**Mode**: `claude-code`
**State at investigation start**: `running`
**State now**: `idle` (auto-recovered ~139s after last output)

## Root cause: regression in `a4b6d8d1` (May 5 2026)

Commit `a4b6d8d1 refactor: drop 'attention' state + remove notification system` deleted the early-return that suppressed completion-stamp false positives.

**Before** (`packages/domains/terminal/src/main/adapters/claude-adapter.ts`):
```ts
// "X for Ym Zs" = completion summary → user can act → attention (= ready for input)
if (/^[·✻✽✶✳✢].*\bfor \d+[smh]/m.test(stripped)) return 'attention'
// Bare glyph at line start = live spinner
if (/^[·✻✽✶✳✢]/m.test(stripped)) return 'working'
```

**After** (current, `claude-adapter.ts:26`):
```ts
if (/^[·✻✽✶✳✢]/m.test(stripped)) return 'working'
```

When the `attention` state was collapsed, the completion-stamp branch was **deleted entirely** instead of remapped to `null`. Result: every glyph line — including post-completion stamps (`✻ Cooked for 56s`, `✻ Cogitated for 4m 24s`) — falls through to `'working'` → terminal state pinned to `running`.

Pre-regression, post-completion was distinct from active-spinner. Post-regression, the two are conflated.

## Compounded by idle-timeout reset behavior

`pty-manager.ts:269 checkInactiveSessions` flips `running → idle` only when `now - lastOutputTime >= idleTimeoutMs` (60s default). Claude Code TUI keeps emitting cursor-move escape sequences (`[3A`, `[2C`, `[?2026h`) for status-bar redraws / cursor-blink. Each byte refreshes `lastOutputTime` → idle timer keeps resetting → state stuck on `running` indefinitely while user looks at TUI.

Once redraws stopped (~139s before re-check), timer fired → `idle`. Self-heal works, but UI shows stale `running` for as long as TUI redraws.

## Fix (minimal, surgical)

Restore the completion-stamp early return, but return `null` (no signal) instead of the now-deleted `'attention'`:

```ts
// Completion summary like "✻ Cooked for 56s" — Claude is done, not working
if (/^[·✻✽✶✳✢].*\bfor \d+[smh]/m.test(stripped)) return null
if (/^[·✻✽✶✳✢]/m.test(stripped)) return 'working'
```

Returning `null` keeps current state unchanged (no false `working` signal). Idle-timeout fallback then transitions to `idle` after 60s of true inactivity.

Optional hardening: in `pty-manager` only refresh `lastOutputTime` when output contains printable content (not pure cursor-move/mode-switch ANSI), so static-TUI redraws don't perpetually reset idle timer.

## Reproduction

1. Open task in `claude-code` mode.
2. Submit prompt; wait until response completes (`✻ Cooked for Xs` shown).
3. While TUI on screen redrawing status bar, run `slay pty list --json`.
4. Observe `state: "running"` despite Claude awaiting input.
5. Wait ≥60s with no TUI redraws → state flips to `idle`.
