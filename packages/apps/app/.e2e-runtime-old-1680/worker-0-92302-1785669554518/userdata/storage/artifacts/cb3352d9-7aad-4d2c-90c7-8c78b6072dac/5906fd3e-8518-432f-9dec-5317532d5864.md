## Phase scope

One-way: local data → running remote server. Built into the Electron app, not a CLI command.

**Tasks:**
- [ ] Wizard UI in Electron settings → "Migrate to remote server". Steps: enter URL → health check → preview (counts of tasks/projects/assets/worktrees) → confirm → progress → done.
- [ ] Tar local SQLite (closed cleanly first) + `assets/` + `project-icons/` + `backups/`. Worktrees: complex (often outside `userData`) — decide whether to copy or just rewrite paths.
- [ ] Upload archive to server via tRPC mutation `migrate.import` (streaming). Server validates, imports, returns receipt.
- [ ] Worktree path strategy: server-side worktree root = `getDataRoot()/worktrees/<taskId>/` (overridable via `SLAYZONE_WORKTREE_ROOT`). Migration rewrites `tasks.worktree_path` to match.
- [ ] Dry-run option in wizard: produce a report (what would copy/rewrite/skip) without writing.
- [ ] Integrity check: round-trip checksums on assets, row counts on tables.
- [ ] On success: prompt user to switch to remote mode (Phase 4 toggle).

**Done criteria:** migrate a real local userdata to a remote server, switch to remote mode, all tasks/projects/worktrees present and functional.
