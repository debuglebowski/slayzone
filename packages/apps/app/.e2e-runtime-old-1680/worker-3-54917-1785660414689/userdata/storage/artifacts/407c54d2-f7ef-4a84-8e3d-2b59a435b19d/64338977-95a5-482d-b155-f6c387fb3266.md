# Skills to create

## 1. `ingest-answers` — raw response → `answers.json`

- Accept any paste format (numbered list, paragraphs, Excel rows, combined report).
- Detect `questionId` by position; strip trailing `Sources:` / `ELAPSED_SECONDS` / START/END markers from `answerText`.
- Extract `citedSources` as `{ source, location? }` — preserve raw naming (SEC filename, local filename, URL), no normalization.
- Validate IDs against `structure.json`.
- Pull timing/cost from the response if present; offer to write `stats.json`.

## 2. `grade-run` — `answers.json` → `answers.verdicts.json`

- Verdicts per question: `{ answer, sources }` each in `correct | partial | wrong | retrieval-fail`.
- Answer: `correct` = all facts + exact numbers · `partial` = some right, precision loss, or supplementary detail wrong · `wrong` = fabricated/contradicted · `retrieval-fail` = honest refusal due to ingestion limits.
- Sources (strict): `correct` = right doc + section/page · `partial` = right doc, missing section · `wrong` = wrong doc · `retrieval-fail` = source unreachable.
- Trap questions: `correct` only when model explicitly states "not in docs". A retrieval refusal is NOT a correct trap handle.
- Include `reason` for any non-correct verdict.

## 3. `scaffold-run` — new competitor run folder

- Args: uc, run, competitor id. Validate competitor in `competitors.json`; offer to add if missing.
- Create `data/<uc>/runs/<run>/<cid>/` with `instructions.md` (title + setup + canonical prompt) and `answers.json` = `[]`.
- Create `run.json` in parent if missing.

## Conventions (all three)

- 2-space JSON indent, trailing newline.
- Preserve raw model output verbatim — grading is the only place rules are applied.
- End with `bun run check`; report warning/error count.
