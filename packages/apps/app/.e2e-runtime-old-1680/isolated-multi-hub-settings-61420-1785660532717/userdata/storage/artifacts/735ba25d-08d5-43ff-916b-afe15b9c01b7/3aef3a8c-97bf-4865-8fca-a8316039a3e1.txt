# Agreements & Policies — Structure & Conventions

_Where Normain's customer-facing agreements and published policies live, and how they're versioned._

## Where things live

| Doc type | Home |
|---|---|
| **Enterprise templates** (Microsoft Marketplace, Customer Cloud Hosting), **NDA**, SLA calculator | `02 - Sales & CS / 04 - Contracts & Agreements / 00 - Customer agreement Templates` |
| **Executed per-customer agreements** (one folder per customer) | `… / 04 - Contracts & Agreements / 01 - Customer agreements (drafts and signed)` |
| **Published / SaaS docs** — Terms of Use, DPA, Privacy Policy, Cookie Policy (Website + Application) | `05 - InfoSec / 02 - Official Other Policies` |
| **Pre-approved subprocessor list** (+ signed vendor DPAs) | `05 - InfoSec / 05 - Vendor Management / 02 - Pre-approved subprocessor list` |
| **Internal ISMS policies** | `05 - InfoSec / 01 - Official InfoSec Policies` |

**`02 - Official Other Policies`** uses a flat numbered scheme: `01. SaaS - Terms of Use` · `02. SaaS - DPA` · `11/12/13. Website - Privacy/Cookie/Terms of Use` · `21/22. Application - Privacy/Cookie`.

## Versioning (snapshots)

- Each doc lives in a dated form: `YYYY-MM-DD - LATEST` (active) · `YYYY-MM-DD - DRAFT` (in progress) · `YYYY-MM-DD` (superseded history).
- Cut a new version when the **offer/agreements change materially** — not per customer, not per minor edit.
- To change: **duplicate the latest → rename to today → edit there.** Never edit a snapshot already used in a signed agreement.
- Exactly **one `- LATEST`** per item; the in-doc effective date matches the folder/file date.
- **Enterprise templates** snapshot the **whole package** together (Main Agreement/Order + attachments) in dated subfolders; **single docs** (policies, subprocessor list) use dated **files**.

## Which document governs which motion

| Document | How it's accepted | Self-serve SaaS | Enterprise – Marketplace | Enterprise – Hosting |
|---|---|---|---|---|
| *Governing contract* | accepted by org/user | Terms of Use (SaaS), click-accept | Order + Microsoft Standard Contract | Main Agreement + Attachment 1 |
| **Terms of Use (SaaS)** | contract | ✅ it *is* the contract | ❌ | ❌ |
| **Privacy Policy** | user notice — not a contract term | ✅ | ✅ | ✅ |
| **Cookie Policy** | user/browser consent — not a contract term | ✅ | ✅ | ✅ |
| **DPA** | legal requirement (GDPR Art. 28) | ✅ click-through (SaaS DPA) | ✅ Marketplace DPA (14-day notice) | ✅ Hosting DPA (14-day notice) |
| **SLA** | commercial — plan-dependent | eligible tiers only | ✅ via Attachment 2 (99%) | ✅ Attachment 2 (99%) |

Privacy & Cookie are accepted by individual **users** (notices/consent), not incorporated into the enterprise contract; the contract's data-protection terms sit in the **DPA**. The **SLA** is a contract attachment (commercial, tier-dependent), not a published policy.

## Publishing (live links)

Customer-facing policies are published from Google Docs "Publish to the web", fronted by `normain.com` 308 redirects:

- `normain.com/product-privacy-policy` → App Privacy (`21.`)
- `normain.com/product-terms` → SaaS Terms (`01.`)
- `normain.com/privacy-policy` → Website Privacy (`11.`)
- `normain.com/terms` → Website Terms (`13.`)
- `normain.com/cookie-policy` → Website Cookie (`12.`) — live (Doc published; Framer repointed; old PDF removed)

**Structure — each *published* policy folder has two parts (different roles):**

- **`00 - Published/`** — the **live** doc (clean-named). This is the **publish-to-web source**, edited **in place**. Its file ID never changes, so the publish URL + `normain.com` redirect stay stable — **no re-pointing, ever**.
- **`YYYY-MM-DD - LATEST/`** (+ older bare-date folders, `99 - old/`) — immutable **version snapshots**, using the **same dated-folder convention as the Customer agreement Templates / Marketplace Template**; docs inside are clean-named (the folder carries the date).
- **Cut a new version:** edit the live doc in `00 - Published`, then **copy** it into a new `YYYY-MM-DD - LATEST/` and demote the prior LATEST → bare date.
- *Unpublished* policies (e.g. `02. SaaS - DPA`, `22. Application - Cookie Policy`) have **only** the dated folders — they get a `00 - Published/` if/when they go live.
