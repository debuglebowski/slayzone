# Concept E — Filtered Task Feed

Flat global task list. Project becomes a filter chip, not a container.

## Behavior

- Sidebar `w-72`
- Top: search + filter chips (project, status, tag, terminal-mode, has-PR…)
- Body: flat list of all tasks across all projects, sorted (recent / due / priority)
- Active project chip narrows to current project (= today's behavior); remove chip → see all
- Each row = task title + project badge + status dot + idle/timer
- Group separators by chosen sort (e.g. "Today / This Week / Older")

## Wireframe

```
┌──────────────────────────┐
│ ≡                        │

│  ◉ refactor api ⏱ [A]   │
│  ◉ ship release    [A]   │

│  ○ migrate db      [B]   │

│  ○ analytics       [A]   │
│                          │
│ — OLDER ─────────        │
│  ○ tutorial scenes [C]   │
│  …                       │
│                          │
│  + new task              │
├──────────────────────────┤
│ ⬢A ⬡B ⬡C +  ⚙          │
└──────────────────────────┘
       w-72
```

Project switcher demoted to footer mini-rail (still draggable).

## Pros

- Most powerful task discovery
- Cross-project work visible — answers "what am I doing?" not "where am I?"
- Filter chips composable

## Cons

- Major UX departure from current model
- Requires sort/group decisions (per-user pref?)
- Project as filter feels weaker than project as place
- Empty state when filter excludes all = needs design
