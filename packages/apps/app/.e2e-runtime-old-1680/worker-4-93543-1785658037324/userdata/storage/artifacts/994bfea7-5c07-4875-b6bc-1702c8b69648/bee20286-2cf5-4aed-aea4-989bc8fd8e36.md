# 1. Change: Kubernetes in production

### **1. Request**

Description:
Move the production Normain service from prior
hosting onto Azure Kubernetes Service (AKS)
managed via Terraform. Introduces
`app-production/workloads` state and OTel
sampling tuning.

Justification:
Enable multi-tenant isolation, horizontal
scaling, consistent deploy pipeline across
dev/prod, and foundation for later network /
secret / audit controls.

Impact:
Full production runtime change. Risk of
downtime during cutover. All subsequent infra
work depends on this baseline.

Rollback plan:
Forward-fix only. Prior hosting was retired as
part of the cutover; reverting would require
restoring prior Terraform state from git and
re-provisioning. Mitigation: parallel run +
traffic shift on the DNS boundary.

# 2. Change: Logical & physical tenant separation

### **1. Request**

Description:
Introduce `customer-tenant` Terraform module.
Each tenant gets its own database, Redis
password, Key Vault secrets, and namespace.
Rename "customers" → "tenants" across code
and config.

Justification:
Required for enterprise customer onboarding,
GDPR data isolation, and blast-radius
reduction. Prerequisite for the
Marketplace/Tenant-API flow.

Impact:
High. Re-keys, re-provisions, and re-shapes
data paths per tenant. Naming change touches
app code.

Rollback plan:
Forward-fix only. Per-tenant state was
created, not migrated; reversing would require
consolidating back into shared infra and is
not practical post-cutover. Mitigation: roll
out one tenant at a time; validate isolation
before next.

# 4. Change: Azure Key Vault for secrets

### **1. Request**

Description:
Replace env-var-based secrets with Azure Key
Vault mounted via the CSI driver and Workload
Identity. Add `terraform/identity` state for
group membership and PIM ownership.

Justification:
Removes secrets from container env and from
1Password provisioning flow. Required for
ISO 27001 A.8.24 (secret management) and
auditability.

Impact:
Every service's secret resolution path
changes. Misconfiguration = startup failure.

Rollback plan:
Revert CSI volume mounts to env vars sourced
from prior secret store. Secrets themselves
remain intact in Key Vault during revert.

# 5. Change: OIDC + Entra ID for service auth

### **1. Request**

Description:
Replace 1Password-sourced service principal
credentials with OIDC-based Azure logins for
tenant-api CI/CD. Add Entra ID SSO for the
worker service. Remove admin certificate
access to the AKS cluster; enforce Azure RBAC.

Justification:
Remove long-lived service principal secrets,
align with "no admin credentials" posture,
meet ISO 27001 A.5.15 / A.8.2 access control
requirements.

Impact:
Every CI/CD pipeline and worker startup path
re-authenticates. Breaking change for legacy
cert-based cluster access.

Rollback plan:
Re-issue SP credentials from stored backup;
re-enable admin certs on AKS via Terraform
variable flip. Azure RBAC remains.

# 6. Change: Audit logging + WORM storage + DB NSG

### **1. Request**

Description:
Enable pgaudit on Azure PostgreSQL, route to
Log Analytics with 365d prod / 30d dev
retention. Add immutable (WORM) storage
backend for pgaudit + Key Vault audit logs
with cool-tier lifecycle at 30d. Add NSG on
the database subnet restricting inbound
PostgreSQL to AKS only. Introduce PIM for
privileged DB access.

Justification:
ISO 27001 A.8.15 (logging) + A.8.20 (network
security). WORM satisfies tamper-evidence
expectations for audit trails. NSG closes a
default-open subnet path.

Impact:
New log volume in Log Analytics + storage.
NSG could block legitimate traffic if
misconfigured. PIM adds time-bound elevation
step for operators.

Rollback plan:
Disable pgaudit extension and detach Log
Analytics sink. Remove NSG rules (re-opens
subnet). WORM policy cannot be shortened
once set — retention remains regardless.
