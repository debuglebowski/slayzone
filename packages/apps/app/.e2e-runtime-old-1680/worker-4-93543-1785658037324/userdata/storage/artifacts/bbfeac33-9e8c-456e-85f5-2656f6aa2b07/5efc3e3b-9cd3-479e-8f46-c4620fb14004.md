# System Map (Bottom-Up, from Code + IaC)

What the Normain production system actually is, derived from `terraform/environments/app-production/{infra,workloads}/` and the source code those workloads run. The SOC 2 draft is **not** an input to this document — it is compared in the separate `proposed-draft-edits.md` v2.

Date: 2026-05-19. Image SHAs in production at time of review: `app` = `3f3269a116f5122a8410d09d06c2c3b17698dbde`, `tenant-api` = `ddbc1ca65ba9d23050390d9f02c3363ab700a880`.

## 1. Workloads running in production

Three deployables, all on the same shared AKS cluster `aks-normain-prod-01`:

| Workload | Image | Triggered from | Purpose |
|---|---|---|---|
| `api` | `normain-api:<sha>` | `build.yml` on push to `main` → `deploy-k8s-prod.yml` | Per-tenant API (Next.js + tRPC + Better Auth). Runs in every tenant namespace. |
| `worker` | `normain-worker:<sha>` | same | Per-tenant background job runner (BullMQ + Redis). Runs in every tenant namespace. |
| `tenant-api` | `normain-tenant-api:<sha>` | `deploy-tenant-api.yml` on push to `main` | Single platform service at `tenant.normain.com` that fronts Azure Marketplace subscription lifecycle and triggers tenant provisioning. |

`slack-bot` module exists in source (`src/apps/server/slack-bot/`) but the corresponding `terraform/environments/app-production/workloads/slack-bot.tf` is **entirely commented out** — not deployed in production. Its env vars (`AWS_BEARER_TOKEN_BEDROCK`) are therefore not active.

## 2. Customer tenants in production

A "tenant" is one instance of (api + worker + Redis + Postgres database + Storage container + NFS share + Key Vault secret prefix + Entra app redirect URI + Cloudflare DNS + per-tenant TLS cert), provisioned by `module.customer_tenant` (`terraform/environments/app-production/workloads/main.tf:432`) with `for_each = local.tenants`.

Three hardcoded/known tenants in production at draft cut-off:

| `tenant_uid` | Domain | DB name | Entra tenant ID | Notes |
|---|---|---|---|---|
| `app` | `app.normain.com` | `normain` | `common` (multi-tenant Entra) | Platform tenant — Free / Starter / Pro / Enterprise self-serve customer organisations live here. `PASSWORD_LOGIN_ENABLED = "true"`. |
| `advisense` | `advisense.normain.com` | `tenant_advisense` | `f57ff8de-4665-4e43-aa05-a46cd1bfad9b` | Customer-specific subdomain, single-org. |
| `miljogiraff` | `miljogiraff.normain.com` | `tenant_miljogiraff` | `59aa7df8-58c4-439d-b0d1-dd1851a86b0f` | Loaded from `tenants.json` (auto-provisioned). |

The `app` tenant is **multi-organisation** internally (organisations created on signup; isolation at app DB row level). `advisense` and `miljogiraff` are **single-organisation** dedicated subdomains.

All three tenants share the same AKS cluster, the same PostgreSQL Flexible Server (`psql-normain-prod-01`), the same Key Vault (`kv-normain-prod-01`), the same ACR, and the same Azure OpenAI cognitive accounts. **No tenant has a dedicated Azure environment.**

## 3. Customer input modes

The platform accepts three reference types (`src/shared/dataSources/src/index.ts`):

| Type | What it points to | Storage path | External service touched |
|---|---|---|---|
| `uploadedFileReference` | A file the user uploaded directly in the UI | Per-tenant Azure Blob container (`sc-uploaded-files-…` or `uploaded-files-tenant-<uid>`) | None for the upload itself; processing pipeline below applies. |
| `entry` | A file/folder in connected file storage (SharePoint, Google Drive, or Box) | Per-tenant NFS share (`dsd-…`) after sync | The three integration providers' APIs (read-only on customer's instance, via OAuth/Graph). |
| `url` | An arbitrary URL provided by the user | Per-tenant NFS share (scraped markdown stored as a file) | **Firecrawl** (`@mendable/firecrawl-js`). |

There is no fourth mode.

## 4. Processing pipeline and third-party calls per data item

Once an item is in storage, the worker (`src/apps/server/worker/`) processes it:

1. **Parse / OCR** — for documents that need layout extraction, `sendDocumentToOcr.ts` ships bytes to **Azure Document Intelligence** (`di-normain-prod-01`, FormRecognizer, Sweden Central).
2. **Transcribe (audio)** — for audio inputs, `src/shared/ai/ai.speech/src/transcribeAudio.ts` calls **Azure Speech** (Whisper deployment on `sweden-normain-prod-01`).
3. **Chunk + embed** — text chunks are embedded via `text-embedding-3-large` deployed on five **Azure OpenAI** accounts (Sweden Central, West Europe, France Central, Germany West Central, Norway East). A `RandomDelegatingEmbeddingModel` (`src/shared/ai/ai.groups/src/index.ts:44`) picks one per request.
4. **Insight extraction (LLM)** — `ExtractInsightWorker.createExtractInsightAgent()` (`src/.../ExtractInsightWorker.ts`) selects:
   - if `ANTHROPIC_API_KEY` is set → `AnthropicExtractInsightAgent` calling **AWS Bedrock** (`AnthropicBedrock`, `eu-west-1`). In production this env var is **not set**, so this branch is inactive.
   - otherwise → `OpenAiInsightsAgent`, which constructs an `OpenAI` client pointed at the Azure OpenAI cognitive_deployment URLs (the `OPEN_AI_GPT_MODELS` env var is wired to `local.infra.ai_models_csv["gpt-5.1"]` from Azure cognitive deployments).
   So in production today, **100% of LLM traffic terminates at Azure OpenAI Service** (Microsoft).
5. **Optional agent tools** — when the Anthropic agent is active (currently never), its toolset includes a `Firecrawl` web-search and URL-scrape tool. The OpenAI insights agent's tool surface should be verified separately if asked.

The `worker` writes outputs back to the per-tenant Postgres database and Blob container.

## 5. End-user authentication into the platform

Configured in `src/apps/server/api/src/utils/auth/client/` using the `better-auth` library (`BETTER_AUTH_SECRET` per tenant).

| Provider | Enabled where | Where the credentials come from |
|---|---|---|
| Microsoft Entra ID (OAuth) | All tenants (`AZURE__ENTRA__CLIENT_SECRET` from Key Vault, `AZURE__ENTRA__CLIENT_ID = 48258497-…`) | Per-tenant `AZURE__ENTRA__TENANT_ID` (multi-tenant `common` for `app`; single tenant for `advisense` / `miljogiraff`) |
| Google OAuth | Platform tenant `app` only (`GOOGLE__OAUTH__CLIENT_SECRET` only injected for `app`) | Google Cloud OAuth client |
| Email + password | Platform tenant `app` only (`PASSWORD_LOGIN_ENABLED = "true"` only in the `app` env block) | Passwords stored locally (better-auth schema) |
| Email verification on signup | All tenants where signup is allowed | Mail via Azure Communication Services |

Session: 7-day expiry, 1-day refresh (better-auth defaults).

**MFA**: not enforced by Normain code; delegated to the IdP (Entra Conditional Access / Google). Out-of-repo verification needed for actual enforcement on customer-org Entra tenants.

## 6. Employee / engineer authentication into Azure

- **AKS**: `local_account_disabled = true`, `azure_active_directory_role_based_access_control { azure_rbac_enabled = true }`. Cluster admin = Entra group `sg_normain_prod_01_terraform_operators`. Members (from `terraform/identity/main.tf`): three engineers (`max@`, `kalle@`, `philip@`).
- **PostgreSQL**: `active_directory_auth_enabled = true` AND `password_auth_enabled = true` (both modes accepted). Developer access via PIM groups:
  - `sg_normain_prod_db_accessor` — server-level Entra admin (PIM-eligible, activation conditions configured in Entra Portal, **out-of-repo**).
  - `sg_normain_tenant_<tenant_uid>` — per-tenant role grant (SQL `GRANT "tenant_<uid>" TO "sg_normain_tenant_<uid>"`). When a developer activates PIM and connects, they authenticate as the group's Entra principal; `pgaudit` logs READ/WRITE/DDL on this role and the `log_line_prefix` captures their UPN.
- **Key Vault** (`kv-normain-prod-01`, `kv-tf-normain-prod-01`): `rbac_authorization_enabled = true`, `purge_protection_enabled = true`, `soft_delete_retention_days = 7`. `terraform_operators` group is `Key Vault Administrator` on both vaults.

## 7. Workload identity (pod → Azure)

`oidc_issuer_enabled = true`, `workload_identity_enabled = true` on AKS. Per-tenant K8s service accounts federated to Azure user-assigned managed identities:

| Service account (per tenant namespace) | UAMI | Azure role |
|---|---|---|
| `keyvault-csi` | `id-kv-csi-normain-prod-01` | `Key Vault Secrets User` on `kv-normain-prod-01` |
| `db-init-entra` | `id-db-init-…` | Entra principal on PostgreSQL server (used during tenant bootstrap only) |

Pod-side secrets are mounted via the Secrets Store CSI Driver as files under `/mnt/secrets-store/<ENV_VAR_NAME>` and read at startup. ACR pulls use the AKS kubelet identity (`AcrPull`).

## 8. GitHub Actions identity (CI → Azure)

OIDC federation, restricted to `repo:normainofficial/normain:ref:refs/heads/main`.

- `normain-github-actions-ci-cd` — `AcrPush` + `AcrDelete` + `Contributor` on ACR, `Azure Kubernetes Service Cluster User Role` on prod AKS + dev AKS. Used by `build.yml`, `deploy-k8s-prod.yml`, `deploy-k8s-dev.yml`, `deploy-tenant-api.yml`, `trivy-scan.yml`, `cleanup-acr-images.yml`.
- `normain-tenant-provisioner` — separate SP used by `provision-tenants.yml` to run Terraform against the prod workloads state.

A Kubernetes `ClusterRole ci-cd-deployer` (`terraform/modules/normain-kubernetes/ci-cd.tf`) grants the CI SP `deployments: get, patch` (sufficient for `kubectl set image`, not full cluster admin).

## 9. Data-plane network isolation

- **PostgreSQL** (`psql-normain-prod-01`, version 16, `B_Standard_B2ms` Burstable): `public_network_access_enabled = false`, private DNS zone bound to the VNet, served from `snet-db` (10.0.3.0/24). NSG `nsg-db-…` allows TCP 5432 only from the AKS subnet (10.0.6.0/24), denies everything else inbound. HA: `zone = "1"` (single AZ) — Burstable SKU does not support Azure PG HA. Backup: `backup_retention_days = 14`, `geo_redundant_backup_enabled = false`.
- **Blob (`uploaded_files`)**: `account_replication_type = "LRS"`, default HTTPS-only (Azure default).
- **Azure Files NFS (`data_sources`)**: Premium FileStorage, `account_replication_type = "LRS"`, `https_traffic_only_enabled = false` (required for NFS protocol), `network_rules.default_action = "Deny"` with subnet allowlist for `snet-api` and `snet-aks`.
- **Audit immutable storage (`audit_immutable`)**: Standard LRS, immutability policy `Unlocked` state with `period_since_creation_in_days = 365` (matches `audit_log_retention_days = 365` from prod infra `main.tf:101`), lifecycle moves to cool after 30 days then deletes after 365.
- **Key Vault**: no network ACLs in IaC (relies on RBAC).
- **ACR** (`acrnormain` global + `acrnormainprod01`): `sku = "Standard"`, `admin_enabled = true`, `public_network_access_enabled = true`.

## 10. Encryption

- **In transit (public ingress)**: HTTPS via Istio Gateway listeners (`https-<tenant>` per tenant on port 443); HTTP listener exists and redirects to HTTPS via `HTTPRoute` filter (`requestRedirect { scheme = "https", statusCode = 301 }`, `terraform/modules/customer-tenant/main.tf:486`). Certs from Let's Encrypt via cert-manager + Cloudflare DNS-01 challenge.
- **In transit (internal)**: Istio service mesh (`asm-1-28`) provides mTLS between pods. NFS share between pods and Azure Files runs unencrypted on the VNet (acknowledged via `https_traffic_only_enabled = false`).
- **At rest**: Azure platform-managed AES-256 across PostgreSQL, Blob, Files, Log Analytics — Microsoft-managed keys (no Key Vault CMK is configured for these resources).
- **Application-layer**: an `ENCRYPTION_KEY` is read from Key Vault and injected into every workload pod (`shared_secret_env_vars.ENCRYPTION_KEY` in `terraform/.../app-production/workloads/main.tf:266`). Used to encrypt selected sensitive fields on top of platform encryption.

## 11. Logging, audit, and monitoring

| Source | Destination | Retention |
|---|---|---|
| Application logs / spans (api, worker, tenant-api, normain-kubernetes) | OpenTelemetry → **BetterStack / Logtail** (`logtail_source.otel`, data region `eu-nbg-2`); `OTEL_SAMPLE_RATIO = 0.7` in prod | 180 days (BetterStack `logs_retention`) |
| PostgreSQL logs incl. `pgaudit` | Azure diagnostic setting → **Log Analytics** `law-normain-audit-prod-01` + **immutable storage** `auinormainprod01` | 365 days (`audit_log_retention_days = 365`) |
| Key Vault `AuditEvent` (main + tf-secrets vaults) | Log Analytics | 365 days |
| AKS node-pool CPU > 80% (15 min avg) | Action group `ag-alerts-normain-prod-01` | n/a |
| Storage account availability < 99% (15 min avg) | Action group `ag-alerts-normain-prod-01` | n/a |
| GitHub code-scanning (Trivy SARIF) | GitHub Security tab | per repo retention |
| ZAP findings | GitHub Issues (`fail_action: false`) | per repo retention |

`pgaudit.log` is set to `NONE` server-wide. The per-tenant PIM group has it overridden to `READ,WRITE,DDL` for developer sessions only — so the audit trail captures developer queries against tenant data, not normal application traffic. `log_line_prefix = "%t-%c-user=%u,db=%d,session=%c,sess_time=%s"`.

Action-group destinations (email / Slack / Pager) are not in IaC — out-of-repo verification needed.

BetterStack uptime monitors are not in IaC — only the log source is provisioned in Terraform. Uptime probes (if any) are configured in the BetterStack UI.

## 14. Things that exist in code but warrant separate attention

- **AKS uses the legacy `kubenet` network plugin** (`terraform/modules/azure/main.tf:162`). Microsoft deprecated `kubenet` for AKS in 2025; new clusters should be on Azure CNI Overlay. Not a SOC 2 description issue, but worth knowing.
- **ACR `admin_enabled = true`** alongside RBAC — a username/password account exists on each ACR.
- **NFS storage account has `https_traffic_only_enabled = false`** (required for NFS); traffic is VNet-restricted but unencrypted on the wire.
- **`pgaudit.log = "NONE"` server-wide** — only PIM-developer sessions are audited (intended, but worth being explicit about in the BCDR / audit exhibit so the auditor doesn't expect application-traffic audit logs).
- **PostgreSQL allows both Entra AD and password auth** simultaneously (`password_auth_enabled = true`). Worth confirming with Security whether password auth is intentionally still on.
