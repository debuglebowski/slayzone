# Asset Versions — Design

## Goal

Version history for task assets (files). Every asset keeps a timeline of content changes. User + agent can read past state, diff, revert, name milestones.

## Storage Model

**Content-addressed blobs.** Unique content stored once; versions point to blobs.

```
asset_versions (
  id            UUID PK
  asset_id      FK → task_assets
  version_num   INT          -- monotonic per asset, no reuse, gaps OK
  content_hash  TEXT         -- SHA-256 of bytes, dedupe key
  size          INT
  name          TEXT NULL    -- optional label; UNIQUE per asset_id when set
  skipped       INT DEFAULT 0 -- 1 = content too large, row only, no blob
  created_at    TEXT
)

asset_blobs (
  hash   TEXT PK     -- SHA-256
  size   INT
  -- bytes stored on disk, not in DB
)
```

- **Hash**: SHA-256 via Node `crypto.createHash('sha256')`. No new dep.
- **No author tracking** — columns dropped to keep schema minimal. Add later if needed.
- **No separate message field** — `name` doubles as label + free-text note.

### Disk layout

- Working copy: `{dataDir}/assets/{taskId}/{assetId}.{ext}` — unchanged
- Blob store: `{dataDir}/assets/.blobs/{sha[0:2]}/{sha[2:]}` — **global**, shared across all tasks for cross-task dedupe

### Why content-addressed

- Handles text + binary uniformly (no diff chain to break on images)
- Free dedupe — identical content = 1 blob, N versions pointing to it
- Cross-task dedupe via global blob store
- Cheap revert — hash → copy blob to working copy
- Extensible toward branching if needed later

### Dedupe illustration

```
Versions table:              Blob files:
  v1 ──┐                      ┌──▶ .blobs/ab/c123  (content: "hello")
  v2 ──┤                      │
  v3 ──┼──────────────────────┘
  v4 ──┐
  v5 ──┼──────────────────────┐
                              └──▶ .blobs/de/f456  (content: "world")
```

5 versions, 2 blob files.

## Version Identity

| Field | Purpose |
|-------|---------|
| `version_num` | Monotonic int per asset. Human/CLI ref (`--version 3`) |
| `content_hash` | SHA-256 of bytes. Storage identity, dedupe key |
| `id` | Row UUID for FK/joins |
| `name` | Optional label (1 per version, unique per asset when set) |

### Rules

- Int never reused. Prune leaves gaps (external refs stable).
- Identical content to previous version → **skip row** (no bump, no dedupe noise).
- CLI `<version>` arg accepts: int (`3`), hash prefix (`a1b2`), name (`before-refactor`), relative (`-N`).
- Reserved names: `HEAD`, `latest`, pure numerics — reject in `rename` / `snapshot --name`.
- Name uniqueness scoped per asset (not global).
- Long / non-unique names supported as labels but can't be used as version ref.

### Relative `-N` syntax

`0` = latest. `-N` = N steps back. Use `=` form if parser complains.

```
Versions:  v1, v2, v3, v4, v5 (latest)

0   → v5    (same as omitting flag)
-1  → v4
-2  → v3
3   → v3    (absolute)
```

Usage: `assets read X --version=-2` or `assets read X --version -2`.

## Named Versions

Version has **one optional name** (nullable column). No separate tags or message tables.

- 1 version = 0 or 1 name.
- `rename` sets/changes the name. Fails if name already used on another version of same asset.
- `rename --clear` removes the name.
- Named versions protected from `prune` GC.

## Write / Append Behavior

**CLI default: every mutation → new version. `--mutate-version` amends latest in place.**
**UI default: always mutate latest version in place.** Explicit snapshot button is the only way to create a new version from UI.

| Caller | Default behavior | Override |
|--------|------------------|----------|
| CLI (`assets write`) | New version | `--mutate-version` |
| CLI (`assets append`) | New version | `--mutate-version` |
| Agent tool call (via CLI) | New version | — |
| UI editor save | **Mutate latest** | Snapshot button creates new version |

### `--mutate-version` semantics

- Like `git commit --amend`.
- Keeps `version_num`, swaps `content_hash` → new blob.
- Old blob → orphan, GC'd by `prune`.
- Preserves invariant: **latest version content = working copy**.
- Rejected on **named** versions (names = stable anchors).

### Tradeoff of UI-always-mutates

- User editing in UI for 2 hours produces 1 version.
- History for UI work only exists via explicit snapshot button.
- Asymmetry: CLI/agent = automatic history; UI = manual checkpoint model.
- Accepted to avoid flooding versions from per-keystroke autosave.

### Streaming use case

```
tail -f app.log | assets append X --mutate-version
```

One version row, content grows. Clean history.

### Restoring old versions

No dedicated flag. Pipe compose:

```
assets read X --version 3 | assets write X
assets read X --version=-2 | assets write X
```

Creates new version pointing to old blob (dedupe, no duplicate blob).

### Explicit snapshot

`versions snapshot -n name` — creates row, honors unchanged content (user intent to mark a moment).

## Write Atomicity

Write = disk update + blob write + version row insert.

**Failure policy: rollback disk on row-insert failure.**

Sequence:
1. Hash content.
2. Write blob to `.blobs/.tmp/<uuid>`, fsync, rename to `.blobs/{hash[0:2]}/{hash[2:]}` (skip if already exists).
3. Write working copy to `<path>.tmp`, fsync.
4. Insert version row in SQLite transaction.
5. On txn success: rename working copy tmp into place.
6. On txn failure: delete tmp working copy. Blob may persist (GC'd later).

Concurrency: SQLite WAL serializes row inserts. No explicit file lock — atomic rename + txn is enough. Last writer wins.

## Large File Handling

**Threshold: 10 MB.** Files above threshold:

- Working copy still updated.
- Version row still inserted (for history linearity).
- `skipped = 1`, no blob stored, `content_hash` = hash of bytes anyway (optional — for future dedupe).
- `read --version N` on skipped row → error: "content not available (exceeded versioning size limit)".
- Diff on skipped row → **error** (content unavailable).

Keeps row timeline continuous without bloating disk on 500 MB videos.

## Orphans

**ELI5:** asset = shelf of drawings. Version rows = numbered list pointing to drawings. Each unique drawing is one physical copy (blob); multiple numbers can share one drawing.

- **Orphan blob** = drawing on shelf no number points to. Dead weight.
- **Orphan version row** = number in list whose shelf (asset) is gone.

Created by:
- `--mutate-version` (hash swapped, old blob unreferenced)
- `prune` (rows removed, blobs may be unreferenced)
- Asset delete (cascade)
- Task delete (cascade via asset)

Cleanup: `prune` scans blob dir, deletes files with zero version rows pointing.

### Asset delete policy

**Cascade delete.** `assets delete X` → remove all version rows for X → blobs become candidates for GC.

## Retention

**Keep everything by default.** No auto-prune. Only `prune` CLI removes history.

### Migration seeding

When schema migration runs on existing DB:
- For each existing asset, create `v1` row with current content.
- `content_hash` computed from current file bytes.
- Blob written to `.blobs/` store (unless size > 10 MB → `skipped = 1`).
- Ensures no asset starts without history.

## Diff

- **Text**: unified diff, **colorized** (ANSI). `--no-color` for piping to files.
- **Binary**: hash + size only. No visual diff.
  ```
  v2  hash=a1b2c3..  size=4096
  v3  hash=d4e5f6..  size=4102
  ```
- **Skipped row**: error.

## CLI — Hybrid (flags + `versions` namespace)

No `vers` alias.

### Commands

| Command | Purpose |
|---------|---------|
| **Existing (unchanged)** | |
| `assets list [taskId]` | List assets in task |
| `assets read <asset-id>` | Read latest content |
| `assets create <title>` | New asset (stdin / --copy-from) |
| `assets write <asset-id>` | Overwrite content (stdin) — **creates new version** |
| `assets append <asset-id>` | Append content (stdin) — **creates new version** |
| `assets delete <asset-id>` | Remove asset + file + cascade all versions |
| `assets upload <path>` | Import file from disk |
| `assets download <asset-id>` | Export raw/pdf/png/html/zip |
| `assets path <asset-id>` | Print disk path |
| `assets mkdir / rmdir / mvdir / mv` | Folder ops |
| **Flags on existing verbs (new)** | |
| `assets read <asset-id> --version N` | Read specific version (default = latest) |
| `assets write <asset-id> --mutate-version` | Amend latest version in place |
| `assets append <asset-id> --mutate-version` | Append, mutating latest version in place |
| **`versions` namespace (new)** | |
| `assets versions list <asset-id> [--limit N --offset M]` | Version history, newest first, paginated |
| `assets versions diff <asset-id> <a> [b]` | Colorized unified diff; `b` defaults to current |
| `assets versions snapshot <asset-id> [--name x]` | Explicit checkpoint (honors unchanged content) |
| `assets versions rename <asset-id> <version> <new-name>` | Set/change version name (`--clear` to remove) |
| `assets versions prune <asset-id> [--keep-last N] [--keep-named] [--dry-run]` | GC old versions + orphan blobs |

### Conventions

- `--task` defaults to `$SLAYZONE_TASK_ID`.
- `<version>` accepts: int (`3`), hash prefix (`a1b2`), name (`before-refactor`), relative (`-N`).
- `--json` for scripting.
- `read` no flag → latest (backwards compat preserved).
- Revert = `read --version N | write` (pipe, no flag).
- `versions list` default order: newest first.
- `prune --keep-last N` keeps by `version_num`.
