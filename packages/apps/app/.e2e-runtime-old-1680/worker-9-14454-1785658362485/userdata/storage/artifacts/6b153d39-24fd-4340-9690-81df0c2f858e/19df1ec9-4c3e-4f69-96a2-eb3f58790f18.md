## Phase scope

Same code, different entry point. Embedded server (Phase 2) gets a thin standalone wrapper.

**Tasks:**
- [ ] New package: `packages/apps/server/`. Add to pnpm workspace.
- [ ] Add to `electron.vite.config.ts` `externalizeDepsPlugin({ exclude: [...] })` if it gets imported by the Electron main bundle (per memory: missing this breaks runtime).
- [ ] `bin/slayzone-server.js` — npm bin entry.
- [ ] `src/index.ts` — boot: bind port (`SLAYZONE_PORT`, default ?), bind host (`SLAYZONE_HOST`, **default `localhost`**, opt-in `0.0.0.0`), init DB at `getDataRoot()`, start MCP, mount tRPC over WS, print banner.
- [ ] **Bundle MCP on the same WS server** as tRPC (single port, multiplexed). CLI / agent CLIs discover MCP URL from Electron settings (or env when running on the server box itself).
- [ ] **Migrate Express local API wholesale** (`POST /api/notify` etc., currently in Electron main) into the server package. No HTTP endpoint stays behind in Electron.
- [ ] **Agent CLI presence check at boot**: server probes PATH for required CLIs (claude, codex, gemini, etc.). **Fail loud and exit non-zero** if missing rather than discovering later in a session.
- [ ] Banner must include: bound URL, data dir, version, **trusted-network warning**.
- [ ] Lifecycle: handle SIGTERM/SIGINT — drain WS, kill PTYs, close DB, exit clean.
- [ ] Config surface: `SLAYZONE_PORT`, `SLAYZONE_DB_DIR`, `SLAYZONE_HOST`, `SLAYZONE_MCP_PORT`, `SLAYZONE_WORKTREE_ROOT`, `SLAYZONE_MAX_UPLOAD_BYTES`. CLI flags as alternative to env.
- [ ] Single-writer guard: lockfile in data dir, refuse boot if held. Prevents Electron-main + standalone server from corrupting same DB.
- [ ] Publishing config — keep unpublished initially (`"private": true`) until ready.
- [ ] Cross-platform sanity check: macOS, Linux, Windows. Node 20 + 22.

**Done criteria:** `cd packages/apps/server && node bin/slayzone-server.js` boots, `/health` returns 200, data dir respected. Identical behavior to embedded mode (same backing code).
