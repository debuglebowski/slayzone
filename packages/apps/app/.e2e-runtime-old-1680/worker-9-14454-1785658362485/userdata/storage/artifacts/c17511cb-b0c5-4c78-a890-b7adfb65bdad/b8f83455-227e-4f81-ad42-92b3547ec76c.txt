OPTION J — Collapsible drawer
==============================

COLLAPSED (default):
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  (tree content — almost full)                           │
│                                                         │
├─────────────────────────────────────────────────────────┤
│  [Boost]  [██░ Claude]  [██░ Codex]              ▲      │  ← bar w/ handle
└─────────────────────────────────────────────────────────┘

EXPANDED (click ▲ or chevron):
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  (tree content — shorter)                               │
│                                                         │
├─────────────────────────────────────────────────────────┤
│  [+task] [zen] [explode] [📁]                           │
│  [agent●3] [panel] [⊟] [⬇]                              │
│  [···]                                  [≡] [⚙]         │
├─────────────────────────────────────────────────────────┤
│  [Boost]  [██░ Claude]  [██░ Codex]              ▼      │
└─────────────────────────────────────────────────────────┘

· Always-visible: usage + handle (one row)
· On demand: workspace + runtime + meta (3 rows)
· State persisted — re-collapses next launch only if user
   chose so (sticky setting)
· Settings = last in expanded view
· Pros:  user controls density, defaults to most tree
         room, expanded = full power
· Cons:  drawer animation = code complexity,
         hidden actions hurt discoverability for new
         users, +1 setting to maintain
