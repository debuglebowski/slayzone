# Handling alert #110 (effect / prisma) without doing the prisma v7 migration

**Alert**: GitHub Dependabot #110 — `effect@3.18.4` — CVE-2026-32887 (high)
**Frameworks**: ISO 27001:2022, SOC 2
**Decision**: Risk-accept with documented compensating controls; track prisma v7 upgrade as future remediation.

## Why this is defensible

The CVE describes: *"Effect AsyncLocalStorage context lost/contaminated inside Effect fibers under concurrent load with RPC."*

Vulnerable code path requires: Effect's `AsyncLocalStorage` / Rpc runtime + concurrent fibers.

Verified non-exploitability in Normain context:

1. **Only consumer of `effect` in our tree**: `@prisma/config@6.19.0`, described in its own `package.json` as *"internal package used to define and read Prisma configuration files"* — a startup-time config parser, not an RPC server.
2. `grep "Rpc\|AsyncLocalStorage"` against `node_modules/@prisma/config/dist/*.js` → **zero matches**. The vulnerable code paths are not invoked.
3. `grep "from ['\"]effect"` against our `src/**/*.ts` → **zero matches**. No direct `effect` usage in app code.
4. `@prisma/config` runs at process startup (when CLI tools or the Prisma client load config), not on the request path.

**Net**: vulnerable execution path is never reached in any Normain process — dev, CI, or production.

ISO 27001:2022 A.8.8 (technical vulnerability management) and SOC 2 CC7.1 do **not** require zero open vulnerabilities. They require an evidenced process:

1. **Detect** — ✅ Dependabot, Vanta integration

3. **Treat** (fix / accept / transfer / avoid) per documented criteria — ✅ formal accept with justification
4. **Review** accepted risks periodically — ✅ quarterly review date set

What auditors look for in a "still-open" finding:
- Justification documented and signed off (✅ above)
- Compensating controls identified (✅)
- Ownership and review date assigned (✅)
- Forward-looking remediation plan (✅ tracked ticket with date)
