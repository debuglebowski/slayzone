# Chromium Fork Implementation Plan

**Chosen architecture**: Chromium fork + Bun sidecar + **Arch B (hybrid native shell)**.

- Chromium fork: minimal patches, owns window + top-level `views::` layout
- Bun sidecar: all current Electron main-process logic intact
- UI regions: each = own `chrome://slayzone-*/` WebUI hosting React subtree
- Browser tab: real `WebContents` as peer `views::WebView` — **truly inline, no overlay**

**Assumption**: near-endless AI dev capacity. Agents run 24/7 in parallel. Human = direction-setter.

## Why this combination

| Goal | Mechanism |
|---|---|
| Full Chrome extension support (MV2 + MV3) | Real Chromium browser, not guest view / Electron |
| Unbroken auth (Google, GitHub, MS, Apple SSO) | Native Chrome UA, full browser context |
| Truly inline browser tab (no overlay clunk) | `views::WebView` peer in same compositor tree |
| Preserve 95% of current Node code | Bun sidecar hosts current `main/` intact |
| Preserve React UI look + Tailwind styling | React runs inside each chrome:// WebView, same tokens |
| Minimize upstream merge pain | ~7 patches, mostly non-core |
| Crash isolation | Sidecar, each UI region, tab — all separate procs |

## Three-tier architecture

```
┌─────────────────────────────────────────────────────┐
│ Bun sidecar (= current Electron main)               │
│  better-sqlite3 / node-pty / Convex / MCP / Express │
└─────────────────┬───────────────────────────────────┘
                  │ JSON-RPC over Unix socket
                  ↕
┌─────────────────────────────────────────────────────┐
│ Chromium browser proc (C++ views layout)            │
│  views::Window + views::View tree + Mojo bridge     │
└──┬───────────────┬──────────────┬──────────────┬────┘
   │ Mojo/WebUI    │ Mojo/WebUI   │ Mojo/WebUI   │ WebContents
   ↕               ↕              ↕              ↕
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────────┐
│ Renderer │  │ Renderer │  │ Renderer │  │ Renderer    │
│ sidebar  │  │ tasklist │  │ terminal │  │ tab content │
│ React    │  │ React    │  │ React    │  │ (real web)  │
└──────────┘  └──────────┘  └──────────┘  └─────────────┘
       ...N regions...                   ...N tabs...
```

## Why Arch B over A / C

| Arch | UI rewrite | Overlay? | Effort |
|---|---|---|---|
| A — fully native (Arc-style) | Entire React → C++ `views::` | None | Massive |
| **B — hybrid split (chosen)** | Split React into N chrome:// apps | **None between regions** | Medium |
| C — React monolith | None | Present (current pain) | Zero |

Arch A = max perf, long rewrite. Arch C = overlay unchanged. **B = pragmatic sweet spot**: keep React, gain true inline.

## Revised patch set

~9 patches (up from 7 — extra 2 for native layout):

1. Branding (name/icon/about/splash)
2. Scheme handlers for all `chrome://slayzone-*/` apps (shared factory)
3. IPC bridge C++ shim → Unix socket to Bun
4. Telemetry strip (UMA, crashpad upload, Safe Browsing phone-home)
5. Default NTP override → `chrome://slayzone-tabbar/`
6. **Custom `BrowserView` subclass**: root `views::View` tree replacing default browser UI
7. **Inline tab widget**: `views::WebView` placement API, `WebContents` from `TabStripModel`, size driven by layout
8. **Multi-region Mojo fan-out**: broadcast state updates to N regions efficiently
9. Optional: native menu delegation via IPC

Patches 1-5 = mechanical, rarely conflict.
Patches 6-8 = substantive, in `//chrome/browser/ui/views/` — occasional rebase.
Patch 9 = deferred.

Total patch surface still << 20. Merge cadence tractable.

## Runtime choice: Bun

| | Node | **Bun** |
|---|---|---|
| Native modules (better-sqlite3, node-pty) | ✅ | ✅ via N-API |
| Startup time | ~100ms | **~20ms** |
| FFI | N-API | Built-in (direct dlopen) |
| TS execution | Needs tsx/ts-node | **Native** |

Fallback: `SLAYZONE_RUNTIME=node` env flag to swap if Bun bug.

## IPC stack

### Tier 1 — Sidecar ↔ Chromium browser proc
**JSON-RPC over Unix socket** (upgrade path: MessagePack over socket).

### Tier 2 — Chromium browser proc ↔ each React region
**Mojo WebUI bindings** — per-region TS Mojo interface (`chrome.send(...)` + event subscription).

### Tier 3 — Cross-region React state sync
**Mojo pub/sub** via browser proc acting as broker. Wrap existing Zustand store — each region subscribes to slices it needs.

|---|---|

| `Menu.buildFromTemplate` | Proxy via IPC |

## Phase 5: Native layout (C++ views)

Custom `views::View` subclass owning layout:

```cpp
class SlayzoneBrowserView : public BrowserView {
  // override ViewHierarchyChanged, Layout, etc.
  // build BoxLayout tree as decomposed
  // each region = WebView ptr member
  WebView* projects_webview_;
  WebView* tasklist_webview_;
  WebView* terminal_webview_;
  WebView* browser_chrome_webview_;
  WebView* inline_tab_webview_;  // real WebContents
  // ...
};
```

Agents generate C++ class structure + BoxLayout wiring. React regions send layout intents (e.g. "hide tasklist") via Mojo → browser proc calls `SetVisible(false)` + triggers reflow.

`views::SplitView` used for draggable terminal/browser divider. Focus via `views::FocusManager`.

## Phase 6: Inline tab widget

```cpp
// Create real tab
TabStripModel* tab_strip = browser->tab_strip_model();
WebContents* tab = WebContents::Create(WebContents::CreateParams(profile));
tab_strip->AppendWebContents(tab, /*foreground=*/true);

// Display inline in our layout
inline_tab_webview_->SetWebContents(tab);
// Now: views::WebView is a child of our layout,
// WebContents is a real browser tab w/ full ext + auth
```

URL bar (React in `chrome://slayzone-browserchrome/`) sends URL via Mojo → `tab->GetController().LoadURL(...)`. Nav state broadcast back. Extensions load automatically (browser-wide session).

## Gotchas specific to Arch B

| Issue | Mitigation |
|---|---|
| Scale-wrap animations across regions | Animate C++ `views::View::bounds` via `ui::LayerAnimator`, React reacts via Mojo resize events |
| Cross-region drag-drop (task DnD) | `views::View` DnD targets + Mojo payload forwarding |
| Keyboard shortcuts (Cmd+W, etc.) | Route through `views::FocusManager` → active region Mojo msg. Cleaner than current `lastFocusedPanelRef` |
| Focus tracking | Native `views::FocusManager` replaces `focusin` listeners |
| Zen mode toggle | `views::View::SetVisible(false)` + BoxLayout reflow |
| React state shared across regions | Mojo-wrapped Zustand. Subscribe per-slice |
| Shadows / rounded corners spanning regions | Paint in shared parent `views::View` over children |
| Dev loop (hot reload) | Each chrome:// app has own Vite dev server, Chromium serves from `localhost:PORT` in dev mode |
| Testing | Playwright can control each region via Mojo; e2e framework needs updating |

## Three-tier risk register

| Risk | Mitigation (w/ swarm) |
|---|---|
| Patch rot from upstream churn | Agents rebase continuously |
| CVE window | Sub-hour SLA via security agent pool |
| Apple notarization edge cases | Agent probes every build |
| Build times | reclient + ccache |
| MV2 sunset upstream | Agents maintain MV2 retention patch |
| Core `//content/` patches needed | Red-team agent review, escalate to human |
| Bun native module breakage | Node fallback via env flag |
| Sidecar IPC latency | MessagePack upgrade, Mojo bridge if needed |
| Cross-region state desync | Eventual-consistent Mojo store, agent tests for race |
| React region Vite coordination | Monorepo turbo setup, agents wire |
| Breaking scale-wrap animation system | Animation regression tests per build |

## Migration strategy

No user big-bang. Channels:

```
slayzone-electron  (current v0.x) ──┐
                                     │
slayzone-next      (beta v2)  ──────┼─→ user opts in
                                     │

```

Electron branch alive during overlap. Agents backport critical fixes both directions.

## Decision gates (human)

- Build green all 3 platforms: approve Phase 2-8 swarm scale-up
- First successful auto-merge cycle: approve agent auto-merge authority
- Sidecar boots + IPC roundtrip works: approve full port sprint
- Inline tab widget renders + survives resize: **validates Arch B pick** — approve region split
- Feature parity 90%: approve beta channel
- <0.1% crash delta vs Electron over 30 days: approve v3 default
- Any `//content/` patch: explicit human review
