# Slice 2.5 — Status & Learnings

_As of 2026-05-22. Side-car `@slayzone/server` shell._

## Status: SHIPPED to main (dark-launch)

Two commits on `main`:
- `e99ba8fa` — feat(server): add @slayzone/server side-car shell (slice 2.5)
- `8e405846` — feat(server): add side-car status panel to Diagnostics settings

The side-car package exists, is spawned + supervised on every app boot, and is observable in the Diagnostics settings tab.

## What the side-car does / does NOT do today

**Does:**
- Spawns on boot as a child process — the Electron binary run with `ELECTRON_RUN_AS_NODE=1` (same native ABI, no rebuild gymnastics).
- Supervised: exponential-backoff restart, 60s healthy-streak reset, `/health` HTTP probe.
- Parent-death detection: self-exits when Electron dies (stdin-pipe close + ppid poll). Verified — no orphans.
- Opens a DB writer handle (WAL; second writer alongside Electron, zero contention because the router is empty).
- Serves `/health` and a `/trpc` WebSocket.
- Logs to `<dataRoot>/logs/sidecar.log` (file, not stdout — back-pressure designed out).

**Does NOT:**
- Serve any feature. `appRouter` is **empty** — zero procedures.
- The renderer does **not** talk to it — still uses the in-process tRPC server.
- No IPC handler migrated.

This is intentional: slice 2.5 is shadow infrastructure. The goal was proving the spawn/supervise/health/DB plumbing in production *before* anything depends on it.

## Key decisions (slice 2.5)

- **Reshape: dark-launch.** Slice 2.5 ships the side-car as shadow infra with zero renderer dependency. The renderer cutover is split into a new **slice 2.6**. This eliminated three risks (test-reset port churn, ~80s mount block, WS reconnect race) and downgraded the macOS Gatekeeper blocker — all of them required a renderer→side-car dependency that does not exist this slice.
- **`ELECTRON_RUN_AS_NODE` over system Node.** The side-car is the same signed Electron binary. It inherits all entitlements + notarization; better-sqlite3's `.node` is co-signed. Gatekeeper risk dropped Blocker → Low.
- **DB stays Electron-owned this slice.** Both processes hold a writer handle (WAL serializes). Migrations stay in Electron main. `SLAYZONE_DB_PATH` is passed verbatim from Electron's resolved path — single source of truth, supervised side-car hard-errors if it is missing rather than guessing.
- **DB abstraction: type alias only.** `SlayzoneDb` in `@slayzone/platform` — no structural interface. Designed from evidence when the first real procedure lands.
- **Static guard** (`scripts/check-server-electron-free.sh`): side-car must not import `electron`; `@slayzone/app` must not import `@slayzone/server` (spawn by path only — keeps it out of the main bundle).

## Learnings / gotchas

1. **Shared-file commit collision.** A sibling terminal-feature commit (`273bbe5e`) accidentally swept this work's uncommitted edits to `preload/index.ts` + `packages/shared/types/src/api.ts` (the side-car status-panel IPC contract). The status panel's contract is now split across `273bbe5e` and `8e405846`. Lesson: `preload/index.ts` and `api.ts` are high-traffic shared files — uncommitted edits there get scooped by whoever commits first. Commit small IPC additions promptly, or expect the split.
2. **Standalone smoke needs Electron-as-Node.** `node dist/bin.js` fails on better-sqlite3 ABI mismatch in a dev install. The standalone smoke must run `ELECTRON_RUN_AS_NODE=1 electron dist/bin.js`. A true plain-Node remote host (slice 7) will need a Node-ABI better-sqlite3 build or a `node:sqlite` swap.
3. **Test the quarantined DMG, not the local `.app`.** Local `build:mac` output has no `com.apple.quarantine` xattr, so it will not reproduce Gatekeeper behaviour — a false pass. The Gatekeeper validation for risk #1 must use a downloaded/quarantined DMG.
4. **Parent-death detection works.** Killing the Electron main process → the side-car self-exits within ~2s (`stopped` in `sidecar.log`). The `pgrep -f` reaper is now only a backstop.

## Open items — gates before later slices

- **HARD GATE before slice 2.6:** the supervisor (~210 LOC, the most logic-heavy new code) has **no automated test**. Crash-recovery e2e was deliberately deferred. It must land before the renderer depends on the side-car in 2.6 — do not let "deferred" become "never".
- **Risk #1 not yet empirically closed:** `build:mac` + quarantined-DMG launch test has not been run. Entitlements look sufficient on paper; confirm in a real notarized build.
- Full `pnpm test:e2e` not yet run for this slice (dark-launch touches no renderer/IPC, so existing specs should pass unchanged — but unverified).
