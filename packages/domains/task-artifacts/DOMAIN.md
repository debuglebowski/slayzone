# Task artifacts

Owns version history, immutable content blobs, working copies and their recoverable file journal.

## Async publication file preparation (S13; integrated by B5/S19)

`@slayzone/task-artifacts/publication-files` exports `prepareArtifactPublicationFiles(options)` and its input/result types. This is an internal file seam for the sole storage owner, not a public RPC or a second DB worker. The canonical chat storage owner uses it for public staged artifact/content and attachment publication. Main reserves source metadata only; no body Buffer crosses the private port. Existing working-copy journal and immutable blob inventories own publication/recovery.

Input:

- `dataDir`: validated, exclusively owned data root; `jobId?`: private UUID, otherwise generated. Creation is exclusive; an occupied job is refused.
- `owner`: path-safe `taskId`, bounded opaque `conversationId` (500 chars) / `operationId` (200 chars), SHA-256 `intentHash`; attribution supplied by the owner after scope/lease checks.
- `source`: validated `path`, expected SHA-256, byte `size`, `identity: { dev, ino }` as decimal strings from bigint stat. The same opened descriptor supplies verified bytes and hash; descriptor/path identity, exact size, EOF and mutations are checked.
- `previous?`: working `path`, optional expected hash/size/identity of an observed working snapshot. Missing initially without an expectation means no before image. Unreadable, nonregular, corrupt expected or concurrently replaced/edited previous input fails. Arbitrary unsaved working bytes are preserved; never compare them to immutable HEAD by default.
- `append?`: after image is previous bytes followed by source, otherwise source alone. Before is preserved for both operations. Bytes remain binary/UTF-8 exact; no content-size cap.
- `signal?`, synchronous worker-local `assertCurrent?`: cancellation/lifecycle checked across asynchronous steps. The owner must register the whole preparation promise before yielding and retain source/execution leases through all closes and failure cleanup. This callback cannot perform asynchronous DB/auth work.

Result: `{ jobId, directory, ownershipFile, source: { sha256, size, identity }, before, after, cleanup }`. Images contain `path`, exact `sha256` and `size`; `before` additionally carries `sourceSnapshot: { dev, ino, size, mtimeNs, ctimeNs }` for publication revalidation, or is null. Only durable files with closed handles are returned. Copies/hash work use bounded buffers and explicit control turns; partial reads/writes are handled. Private output files are owner writable (`0600`), directories `0700`. File sync errors propagate; directory sync follows existing journal policy (POSIX sync, Windows skip).

Preparation creates `<dataDir>/artifacts/.transactions/<UUID>/owner.json`, then `before` when present and `after`. The bounded version-1 header names `kind: artifact-publication-preparing`, all owner fields, logical `jobId` and a private `cleanupToken`. The header and parent directory chain are durable before any body is copied. Images and their directory are durable before success. `cleanup()` is asynchronous/idempotent and identity-bound: it claims its own directory at a fresh UUID, verifies ownership on retries, removes body images durably before the header, then removes the empty directory. Native failures propagate and may be retried; retained content keeps attribution. It returns `removed`, `absent` or `replaced`. `absent`/`replaced` concern the captured location, not a task-wide erasure certificate. A claimed cleanup directory retains the original logical `jobId` in its header. Cleanup never removes the supplied source/previous paths or an occupied/reused job. Unknown files indicate adoption by the journal owner and refuse helper cleanup.

Canonical owner integration invariants (implemented by B5/S19):

1. Inventory both preparing `owner.json` and existing `manifest.json` under `.transactions`, including claimed cleanup directories. Fence ordinary recovery/task/account erasure against active jobs; wait for native I/O and cleanup before erasure verification. Recovery inventories attributed preparing jobs before reconciling missing manifests; it never runs concurrently with a live helper. Header corruption must follow conservative erasure/quarantine rules rather than silently skip private bytes.
2. Revalidate authoritative task/account/epoch, artifact membership, source lease, current version and working-file snapshot after preparation and again at the short publication fence. A before snapshot is not a lock on an external editor. DB current/locked-version/history/dedup decisions remain in the existing sole owner. Missing/deduplicated/no-op flows still dispose their private images.
3. Feed verified private images into the existing working-copy journal protocol; preserve its `FileChange` fields, sequence/DB commit marker, durable before/after/manifest ordering, final working-file rename and later-editor-aware rollback/recovery. Preparation never writes a manifest/marker or final working path. The owner may durably adopt the job directory or transfer images to its journal; adoption transfers cleanup to the journal owner. Do not call helper cleanup on an adopted journal, or pass prepared paths to an old synchronous full-file reader on the main thread.
4. Publish immutable bytes from the prepared after image asynchronously/off-thread; keep durable blob/file publication before the atomic DB version/current-pointer/receipt decision and final acknowledgement. Hold leases until actual execution quiesces, even when a logical response times out or cancels. Source deletion/release belongs to that owner, after its existing retry/idempotency decision.
5. Actual public-invoke tests exercise the packaged owner and real main manager: large append/previous bytes, native FULL fence/control responsiveness, failures, source/lifecycle replacement, erase/close/replay and compaction swap. S13 helper tests remain the lower-level file proof. Final FU2/S8/current-main integration and independent R6 review remain root work.

Tests are collected by the existing task-artifacts package runner in `packages/shared/test-utils/run-all.sh`; no duplicate harness registration is needed. The publication contract at `../fu-1-artifact-publication-contract.md` (worktree sibling) specifies the wider owner/lease command seam; it is not implemented by this helper.
