The key migration repair

1 · COPYPrompts have a stable ownerClosing a chat tab cannot change task-wide ownership.
2 · VERIFY + ACTIVATEKeep proof of exactly what movedThe destination and source agree on the verified transfer.
3 · CLEAN UPDelete only proven copied contentInterrupted or superseded work cannot erase uncopied data.
The computer owns durable chat content. The hub keeps routing, lifecycle and migration metadata.

The nine repairs

✓F34 · MigrationClosing a tab during migration can erase uncopied promptsFixed

BeforeCleanup elects B as the new content owner and deletes task-wide prompts that were absent from its verified transfer. The normal service retry succeeds after the data is lost.

NowTask-wide prompts have their own durable owner. Cleanup deletes only source rows proven present in the verified transfer.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F35 · MigrationMixed-computer migration creates conflicting session ownersFixed

BeforeEach transfer contains every task provider session. The first recovery claims both sessions; the second fails with Provider conversation belongs to another storage owner.

NowHistorical session metadata no longer claims every provider session. Proven old cross-provider misclaims are repaired; real owner conflicts stay fenced.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F36 · IntegrationSwitching chat provider leaves the new provider unusableFixed

BeforeThe tab retains its immutable Claude storage binding. Codex hydration fails with Chat tab ownership mismatch; the selected provider cannot open.

NowProvider changes stop and fence the previous writer, archive its history and queue, and copy the unsent draft to the selected provider. Interrupted changes resume safely.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F37 · Content safetyA rejected queued message clears text and attachmentsFixed

BeforeThe composer clears before remote queue admission succeeds. A rejected admission leaves no input, queue entry or failed-message bubble. Desktop is reproduced; the equivalent mobile path is source-confirmed.

NowPending sends persist locally before RPC with one stable ID. Failed or ambiguous sends retain text/files; retry cannot duplicate an accepted send or clear newer edits.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F38 · Content safetyTyping during the first offline load has no durable draftFixed

BeforeLocal journaling waits for the first successful remote read. No local journal or server save exists, so the only draft copy disappears.

NowTyping is journaled before the first remote read. Owner/revision conflicts preserve both drafts; late saves are fenced and valid unsent copies never expire by age.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F39 · RetriesRetrying a drained message can permanently block its queueFixed

BeforeA duplicate queue row is created. The outbox already knows that message and emits no new user-message event to remove it. The duplicate remains at the head and later messages never reach the provider.

NowA task-wide, content-free message identity index survives drain, retention, provider changes and tab deletion. Reused IDs cannot start another provider turn.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F40 · ReconnectA short computer disconnect leaves the visible chat staleFixed

BeforeThe answer is safely stored on the computer, but no replay/invalidation reaches the open chat. Availability is sampled ready before and after, so the shared desktop/mobile hook never reloads history.

NowA recovery/binding watermark and explicit signal reload missed output even if availability was always ready. Hidden tabs and in-flight status requests catch up safely.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F41 · DurabilityA failed purge can delete the only working file copyFixed

BeforeThe task and artifact rows return to an active state, but the unversioned file bytes are already gone. An injected final SQL abort reproduces this rollback window.

NowDeletion first commits its tombstone and cleanup intent. File removal happens afterward, with startup and IO-failure retries.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
✓F42 · RetentionTool metadata can retain expired attachment bytesFixed

BeforeRetention recursively treats opaque tool data as an attachment reference. The expired attachment pin and private bytes survive; the control without similarly shaped metadata is collected.

NowRetention recognizes normalized user attachment references and ignores attachment-shaped tool input.

Original failing reproduction retained in the canonical JSON; current regression suites pass.
