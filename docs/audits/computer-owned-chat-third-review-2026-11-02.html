P1F22 · new findingRolling upgrade falsely advertises a compatible computer+
Trigger
Current supervisor/connector reuse a real prefeature session host while a harmless native job is still running.
Observed
Connector advertises wire protocol5, but retained host lacks chat.request and replies -32001. New recovery barrier blocks file access, terminal kill and the running job’s proc.kill. Host maintenance waits for idle while normal stop controls are blocked.
Cause
Host contract stays1 across incompatible dispatch changes. Connector advertises its own protocol and release instead of proving the host can serve those methods. Host reuse/maintenance compares release version without build identity.
Repair
Negotiate/version host chat capability before connector handover. Never advertise unsupported protocol. Coordinate required maintenance and retain safe stop controls without bypassing ownership/deletion fences.

P1F23 · new findingImported native history does not acquire its own attachment pins+
Trigger
Real Codex driver imports saved attachment references into a sibling conversation. Expire or delete the source chat.
Observed
Retained imported message still references the file, but source pin removal lets GC erase its sealed blob. Attachment becomes unreadable. Reproduced for both retention and source-tab deletion, with zero turn/start calls.

Native history enrichment reads task-wide saved content without creating a durable destination-owned attachment reference. Retention counts references only inside the source store owning the pin.

Controls that passed

  • Real WebSocket refuses an older wire protocol before authentication.
  • Timed-out committed draft replays one receipt across reconnect; revision remains1.
  • Successful notification ACK drains the durable host journal.
  • Default-off retention preserves zero-clock pins and long queues across restart.
  • 1,205 queued items and sequence fences survive batched expiry correctly.
  • Archive paging returns sparse events and mixed/oversized records exactly once.
  • Ordinary sealed history survives original-version pruning, deletion, GC and reopen.
  • Public uploads use separate task-file stores; originals remain discoverable after chat deletion.
  • Reset, fork/rewind, in-flight deletion, child/parent deletion fences and Trash/undo controls pass.
  • Mixed hub/A/B folder download preserves tree names and exact bytes; task rebind preserves original file ownership.

Candidates excluded from the count

Offline global search: an unrelated offline computer makes the request fail explicitly. Returning partial results may be preferable, but the per-computer partial-results contract is unresolved; no extra finding counted.

Hidden archive originals: an early low-level fixture put original files under an ordinary chat owner. The real public upload path uses a separate task-file store and passes discovery/download after chat deletion. Suspicion withdrawn.

Cross-PC folder misfiling is reported as temporary and self-healing after another A recovery; bytes are not lost. Archive queue omission is a recovery/export gap, not live queue loss. Child-list finding does not assert a separate privacy-erasure promise.

Repair priorities

Make rolling capability claims truthful

Version the host contract, validate chat support before handover, and preserve safe maintenance/stop paths while existing work runs.

Account for every durable content reference and copy

Destination pins on import; deletion/retention coverage for host journals; session identity survives content expiry; thread references track deletion.

Finish read-only recovery

Expose unsent queue content and sealed attachments without replaying operations. Keep prior backup-verification and transition-source fixes in scope.

Enforce one API contract across storage backends

Global search limit/filtering/counts, explicit folder destination, ordered ownership reconciliation, raw current-file reads and author metadata.

Implement fixes before stability certification

All three reviews target unchanged production code. Re-run accumulated regressions, whole upgrade/restore replay and independent review against the corrected implementation.

Unresolved questions: partial global-search policy; upgrade UX while incompatible active work remains; archive queued-message presentation. No existing functionality should be removed to meet these constraints.
