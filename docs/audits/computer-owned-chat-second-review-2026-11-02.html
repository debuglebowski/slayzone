Eight new feature findings

All reproducible on disposable stores through production code. Open a row for conditions, source and repair constraints.

P1F14 · new feature findingFirst prompt-history bootstrap can wedge the computer+
Trigger
Open prompt history on a fresh native task; disconnect before bootstrap reaches the computer.
Observed
Hub already marks the prompt-history store active. Computer has no store. Reconnect metadata snapshot rejects; normal commands including terminal stop are blocked.
Cause
ensurePromptTask registers active ownership before remote bootstrap ACK. This has no migration to activate, unlike old F02.
Repair
Reserve a durable initializing owner before creation, fence task/tab deletion, bootstrap idempotently, publish active only after matching ACK. Recover incomplete initialization explicitly.

P1F15 · new feature findingReconnect overwrites current settings with stale sibling values+
Trigger
Two active tabs share a provider. Change model/mode/session on selected root, then reconnect with an untouched sibling.
Observed
Actual endpoint tests revert plan → normal, opus → sonnet, and new-session → old-session. Both stores are active; this is distinct from old F07 prepared-store selection.
Cause
Each tab caches provider configuration. Recovery replays every sibling by storage ID into task-global settings, with no authority/revision rule. mirrorProviderConfig=false protects conversation records, not provider-config updates.
Repair
Define task/provider configuration authority and revision across bootstrap, edits and replay. Restore current state deterministically; do not disable recovery or rely on storage-ID order.

P2F16 · new feature findingClosing a tab during first bootstrap resurrects it+
Trigger
Computer commits first bootstrap; hold reply. Delete the actual terminal tab while no hub owner exists. Release reply and reconnect.
Observed
Late registration publishes an active locator; recovery recreates the deleted visible tab.
Cause
Ordinary chat creates remote storage before publishing its locator. Delete trigger has no owner to tombstone in that interval. Simply reversing order causes F14-style missing-store failures.
Repair
Use initializing reservation plus per-tab deletion fence and a conditional post-ACK activation. Apply the protocol to all store creators, not just prompt history.
Sourcehub-relay.ts:126–128; hub-ownership.ts:101; hub-recovery.ts:105Proofrecovery-second-pass.test.ts — deleting a tab while its first bootstrap reply is pending
P2F17 · new feature findingConcurrent retries of one upload create two files+
Trigger
Send two simultaneous strict artifact RPC requests with identical operation ID and input.
Observed
Both requests create different artifacts. Sequential retry correctly returns one cached result; concurrent reuse with different input is correctly rejected.
Cause
Artifact receipt is checked before asynchronous scope checks. acceptCommand later returns duplicate, but its result is ignored and both mutations continue.
Repair
Join identical in-flight operations using conversation + operation ID, while validating input hash before joining. Keep durable accepted-but-unconfirmed behavior after process death.

P2F18 · new feature findingAcknowledged tab deletion leaves raw transfer history+
Trigger
Stage a migration, delete the tab before activation, deliver deletion and ACK, then restart computer.
Observed
Hub and computer are tombstoned; cleanupPending=false and source rows are gone. Raw transfers/*.data still contains deleted history indefinitely.
Cause
Conversation tombstone does not erase transfer staging; collectActivated only handles active stores.
Repair
Erase transfer state per conversation idempotently, retry on startup, and acknowledge deletion only after required cleanup completes. Preserve unrelated stores and deliberate backups.

P2F19 · new feature findingFailed uploads retain private temp bytes after deletion+
Trigger
Partially write a sealed attachment then fail with ENOSPC. Permanently delete task, reopen, run both garbage collectors.
Observed
Flat .upload-* file retains partial private payload after deletion/restart. Sharded temp files have an inherited version of the same problem.
Cause
writeBlob closes the descriptor on failure but does not remove its staging file. Collector ignores filenames that are not complete hashes.
Repair
Clean every failed staging path; safely track/collect abandoned staging across restart and retry cleanup failures. Do not remove active uploads blindly.

Observed
Answer is absent from event/record history but survives verbatim in receipt.result. Domain contract explicitly says no DB persistence; answer should live only in renderer card.

First review: strengthened, not resolved

The original 13 findings remain open, including unsafe transition backups, interrupted activation, mutable attachment manifests, dormant hub content and slow metadata reads. These two received additional independent proof:

F03 · Old-backup reconciliation is still broken

Independently reproduced using actual SQLite backups rather than manually rewound locators. Legacy snapshot + prepared destination conflicts. Snapshot predating locator creates a second storage ID; old prepared store remains and native admission rejects Task chat migration is pending. Copying snapshot + prepared destination is a passing control.

F11 · Archive verification needs semantic completeness

In addition to omitted blobs, unsupported schema, missing events table and malformed event JSON can become verified archives. Missing table/invalid JSON archives later fail reads. Malformed JSON came from the disposable live store before normal backup.create. These are expansions of F11, not three new defects.

Inherited risks, kept separate

Real defects exposed through computer-owned storage, but not all introduced by this migration. They still matter to a dependable artifact experience.

Inherited · not a new migration regressionWorking original and committed HEAD diverge+

ENOSPC or an invalid historical ref rejects the write after changing the visible original. Mutating old v1 can also leave original showing v1 while HEAD is v2. Survives reopen. Shared artifact-store transaction code predates this feature.

What passed under stronger testing

True process termination

  • Metadata checkpoint commit.
  • Chunk data fsync before progress save.
  • Progress-file rename.
  • Stage row inserted before SQLite commit.
  • Prepared transaction committed.
  • Activation transaction committed.

All six recover after actual SIGKILL. This does not prove survival of hardware power loss; progress JSON still lacks file/directory fsync.

Behavior and integrity controls

  • Approval blocks queue, then FIFO resumes.
  • Wrong-conversation conclusions block later queue entries.
  • Provider failure/restart Retry saves one user event and sends once.
  • Draft revisions, separate tab drafts, metadata ACK retry and recovered queue routing.
  • Actual SQLITE_FULL preserves committed append history; repair allows retry.
  • Snapshot lease preserves originals through concurrent edit/deletion/GC.
  • Flat sealed reads reject corruption and verified uploads repair it.
  • Chat deletion preserves separately owned original files.

Implementation gates before calling this smooth

One lifecycle protocol

Durable initialization, crash recovery, orphan prepared reconciliation, conditional activation, and deletion fencing. Fix fresh creation and migration as one state matrix.

One configuration authority

Version task/provider state and preserve native handoff semantics. Stop replaying stale sibling caches into authoritative settings.

Explicit operation policies

Single-flight durable mutations keyed by owner + operation ID; hash-conflict rejection preserved. Separate idempotency from ephemeral result retention.

Complete file transactions and cleanup

Freeze historical versions; validate archive schema/content; defer irreversible unlink until committed GC work; remove raw transfer and failed staging payloads before claiming deletion complete.

Run the full evidence set against fixes

All first- and second-pass invariants, actual process kills, whole old-backup replay, byte comparisons, deletion/restore matrices, UI and remote-latency coverage. Then independent review of the corrected implementation.

Unresolved questions: whether this review should also implement fixes (scope question pending); transitional backup policy; safe repair of already-generated tabs. Review does not establish bug-free behavior while confirmed defects remain unfixed.
